## 3. 코드에서 찾은 버벅임 원인

1. **이름표를 매 프레임 DOM으로 옮겨요.** 사람·NPC마다 `div.ntag`가 있고, 그리는 루프마다 `style.left/top`을 다시 써요(`world_tpl.js` 719행). 사람이 늘면 레이아웃 계산이 계속 일어나요. 누군가 들어오거나 나갈 때마다 이름표를 전부 지우고 다시 만들어요(`retag`).
2. **시트는 바뀔 때마다 통째로 다시 만들어요.** `render()` → `frame()`이 `innerHTML`로 패널 전체를 새로 쓰고 이벤트를 다시 붙여요. 재료 하나 넣어도 도감 100칸까지 다시 그려서, 느린 기기에서 77ms 긴 작업이 생겨요.
3. **`setInterval`이 15 개 돌아요.** 위치 동기화, 초대 확인, 행사 띠, 꾸미기 미리보기(160ms), 요리 타이머 등이 화면과 상관없이 같이 돌아요.
4. **글꼴을 4 개 받아요.** `G11` 이름에 Galmuri11과 Galmuri7이 같이 걸려 있어서 둘 다 내려받고, 미리 불러오기(preload)가 없어요. 한글 전체 글꼴(서브셋 아님)이라 첫 화면이 늦게 떠요.
5. **한 파일 번들.** 모든 화면 코드(약 400KB)와 지도 메타(약 500KB)를 첫 화면에서 한꺼번에 받고 해석해요. 화면별로 나눠 받지 않아요.
6. **Firebase**: 위치는 칸이 바뀔 때만 써서(`presTick`) 걸음마다 쓰지는 않아요. 다만 실시간 리스너가 18 곳이고, 저장(`save`)은 0.3 초 뒤 플레이어 문서 전체를 통째로 덮어써요. 저장 상태 표시가 없어요.
7. **캔버스**: 맵·캐릭터는 이미 캔버스 하나에서 `requestAnimationFrame`으로 그리고, 정수 배율·`pixelated`예요(좋음). PC처럼 화면이 크면 그리는 면적이 커져서 4배 감속에서 30fps까지 떨어져요. 화면 밖 물체를 거르는 처리는 있어요.

## 6. 고칠 순서 제안

지시서 8 장 순서대로 하되, 효과가 큰 것부터:
1. 디자인 토큰·공통 패널 틀 → 게임 셸(상단 HUD 56px · 하단 메뉴 64px · 상황 버튼), 시트를 화면 높이 안 패널로
2. 솥·요리·옷 가게·내 방·낚시를 탭/페이지 넘김으로 나눠서 패널 안쪽 스크롤 없애기(솥: 레시피·솥·재료 한 화면, 도감은 별도 탭)
3. 글꼴: 본문 Pretendard(서브셋, 직접 호스팅, preload), 픽셀 글꼴은 제목·버튼만, 최소 15px·대사 17px
4. 성능: 이름표를 캔버스로 그리기, 시트 부분 갱신, interval 정리(보이는 화면만), 글꼴 2 개로, 이미지 WebP
5. 새 기능: 가방 → 내 정보 → 관계 → 일지 → 메뉴·설정·로그아웃
6. 자동 테스트 `tests/ui.spec`(스크롤 0 · 13px 미만 0 · 대비 0 · 터치 44px · 패널 열고 닫기 · 로그아웃 · 솥 흐름 · FPS)

측정 방법 메모: FPS는 `requestAnimationFrame` 간격, 긴 작업은 `PerformanceObserver('longtask')`, 입력 지연은 Event Timing API, 대비는 axe-core 4.10 `color-contrast`, Lighthouse 12.2(모바일, 로컬 서버라 실제 네트워크보다 빠르게 나올 수 있어요).
