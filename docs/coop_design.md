# 협동 탐험 설계 (확정 사항 + 진행 단계)

## 확정된 규칙
- 파티는 **실제 플레이어만** (1~5명). 인원이 모자라도 **AI 동료는 넣지 않아요.** (혼자면 나 혼자 싸워요)
- 전투 중 **접속이 끊기면** 그 사람은 파티·전투에서 **사라져요** (자리를 AI가 대신하지 않아요).
- **탐사가 끝나기 전에 다시 접속하면** 같은 파티에 **다시 참여**할 수 있어요 (진행 중인 방 목록에 「돌아가기」).
- 보상은 나누지 않고 각자 받아요. 길은 파티원 투표(15초, 과반수, 동률이면 방장).
- 전투 계산은 방장 기기가 하고 멤버는 행동 명령만 올려요 (설계서 5장). 방장이 끊기면 다음 사람이 이어받아요.

## 진행 단계
0. ✅ AI 동료 제거 (혼자 탐사는 나 혼자, 몬스터 수는 인원에 맞춰 줄임)
1. ✅(개발자 전용, 주소 끝 ?coop=1) 방 만들기·참가·로비 (지역 고르기, 준비, 출발)  → `xparty/<방>`, DB 규칙 추가
2. ✅ 파티 전투 (방장 계산 → xrun/<방>/bt, 멤버 명령 → in/<uid>/cmd, 끊김은 전투에서 빠짐)
3. ✅ 길 선택은 투표 대신 **선착순**(먼저 누른 쪽), 돌발 상황은 각자 반응(못 한 사람만 피해)
4. ✅ 결과 정리 (보상은 각자, 중도 이탈·재접속·방장 이어받기, 시간/전멸/클리어 종료는 모두에게)
5. ⬜ 관리자 직업 창 (협동과 별개)

## 구현 메모 (xrun/<방>)
- u/<uid> 전투용 능력치 · rs 진행 상태(방장) · bt 전투 장면(방장, 5Hz) · in/<uid> 입력(fk 갈림길, hz 돌발, cmd 전투 명령)
- 하트비트 5초, 20초 조용하면 끊긴 것으로 봐요. 방장이 끊기면 남은 사람 중 uid 순 첫 번째가 이어받고, 전투 중이었다면 같은 체력으로 새 전투를 시작해요.
- 방장 기기가 탐사 화면을 닫으면 진행이 멈춰요 (방장 화면이 시계 역할).
- 시험: `tools/ui_mock.sh` 의 모의 DB는 같은 브라우저의 여러 창끼리 BroadcastChannel로 공유돼요.
- DB 규칙(`database.rules.json`)에 xrun이 추가돼서 Firebase에 규칙을 올려야 실제 서버에서 돼요.
