# 하트 이벤트 대본 맥락 수정 지시서 (2026-10-19, 사용자 원문)

대본 100 개 이벤트를 NPC별로 전부 읽고 맥락을 검토한 결과야. 큰 줄거리와 복선 회수는 10 명 모두 앞뒤가 맞아. 고칠 건 주로 **분기를 오갈 때 생기는 어긋남**과 **NPC끼리 서로 다르게 말하는 사실**이야.
아래 순서대로 고쳐 줘. 대사 분량과 감정선은 유지하고, 필요한 줄만 바꾸거나 덧붙여.

> 참고(작업 메모): 검토자는 대본 HTML을 읽었어요. HTML은 `{sera.name}` 같은 변수를 기본 이름(세라·루카스·마들렌…)으로 풀어서 주황색으로 보여 줘요. 실제 데이터에는 이미 변수로 들어 있어요(1-5). `<npc>_was_cold`는 엔진이 이벤트를 마칠 때마다 그 이벤트 결과로 덮어써서, 바로 앞 이벤트가 서먹하게 끝났을 때만 켜져요(1-3). `<npc>_hN`은 그 이벤트를 보면(좋은·서먹한 결말 모두) 엔진이 자동으로 켜요(1-2 마지막 줄).

## 1. 시스템 차원의 수정 (먼저)

### 1-1. 분기 한정 사실을 공통 대사가 전제하는 문제 (가장 많음)
한 선택지 분기에서만 나온 말·행동·물건을 합류 구간이나 다음 이벤트가 "모두가 겪은 일"처럼 말하는 곳이 NPC마다 5~10 군데씩 있어.
- 검증 스크립트에 이 검사를 추가해: 각 대사가 앞 이벤트의 특정 분기 라벨에서만 등장한 고유 표현(따옴표 인용, "~라며", "~했잖아", "그때", "처음 만난 날")을 되받는지 찾고, 해당 분기 플래그 조건 없이 쓰였으면 경고.
- 고치는 방법은 둘 중 하나:
  1. 그 분기 선택에 플래그를 남기고 대사를 `if_flag`로 나눔
  2. 어느 경로에서도 말이 되는 표현으로 일반화
- 아래 3 장의 NPC별 목록에 있는 항목은 전부 고쳐.

### 1-2. 플래그 설정 지점 명시
- 대본 내보내기에 플래그를 **세우는 곳**이 안 보여. 모든 선택지와 결말에 `set_flag`를 명시하고, 대본 HTML에도 "▶ 플래그: xxx" 표시를 출력해.
- 이름과 실제 선택이 어긋나 보이는 것 확인:
  - `kappa_quiet_seat` → 대사는 ♥1 c2_point(찌를 가리킴)를 전제함
  - `aula_stayed` → ♥5 c2_sit에 대응하는지
  - `madeleine_player_share` → ♥9 c1_honey, c1_wheat에서만 (c1_taste 제외)
  - 마들렌 `dark_kitchen`과 ♥5 "새벽 세 시" 대사의 분기(c3_call) 불일치
- 다른 NPC 진행 플래그(`aula_h8`, `batri_h9`, `sera_h10`, `madeleine_h5` 등)는 해당 이벤트를 마치면 엔진이 자동으로 남기게 해.

### 1-3. `*_was_cold`(서먹한 결말) 플래그 수명
- 지금은 한 번 켜지면 꺼지는 곳이 없어서, 이후 모든 이벤트가 엉뚱한 사과로 시작할 수 있어(스트로, 스텔라, 맨디, 레오 등 전부 해당).
- 이벤트 시작 시 소모하고 지우기 → 그 이벤트가 서먹한 결말로 끝날 때만 다시 켜기.

### 1-4. 서먹한 결말 경로의 아이템·장면 누락
서먹한 결말이 일반 ending을 대신하면서, 이후 이벤트가 전제하는 물건이나 장면이 빠지는 경우야. 서먹한 결말에도 핵심 물건 전달과 핵심 정보는 짧게라도 넣어.
- 나비 ♥8 서먹 → ♥9 cold_open "방울 소리가 딸랑" (방울을 다시 끼우는 장면 없음)
- 캇파 ♥7 서먹 → ♥8 cold_open "보름에 오라던 말" (초대 없음)
- 아울라 ♥3 서먹 → ♥4 cold_open "야간 열람증" (받은 적 없음)
- 맨디 ♥8 서먹 → ♥9·♥10 "아울라 선생님이 팻말을 떼어 감" (장면 없음)
- 스텔라 ♥8 서먹 → ♥9 "월장석 목걸이" (받은 적 없음), ♥5 서먹 → 별똥별 조각
- 레오 ♥9 서먹 "포대 글씨를 지움" → ♥10 그 글씨가 그대로 있음
- 마들렌 ♥9 서먹·♥10 cold_open "맨 위 칸 비워 둠" ↔ 이미 재료를 낸 플레이어

### 1-5. 사람 NPC 이름 변수
다른 NPC 대본 속에 사람 NPC 이름이 고정 글자로 들어가 있어. 전부 `{npc.name}` 계열 변수로 바꿔.
- "세라", "루카스" → 배트리 ♥8·♥10, 캇파 ♥7, 아울라 ♥9·♥10, 맨디 ♥7·♥10, 스텔라 전반
- "마들렌" → 스트로 ♥7, 스텔라 ♥7~♥10
- 검증 스크립트의 고정 이름 검사를 **모든 NPC 파일**로 넓혀.

### 2-1. 이벤트 열리는 순서 조건 (교차 의존)
아래 이벤트는 다른 NPC 이야기가 먼저 진행돼야 말이 돼. 열리는 조건에 추가하거나, 진행이 안 됐을 때의 대체 대사를 넣어.
- 세라 ♥9·♥10 ← 아울라 ♥8(돌아온 책장), 맨디 ♥7(뿌리), 캇파 ♥7(이슬)
  - 지금 au_yes/au_no 분기는 있으니, 맨디·캇파도 같은 방식으로 분기를 추가해(진행 전이면 "시장에서 구한 재료"로).
- 세라 ♥5(서고 밀담) ← 아울라 쪽 진행과 상관없이 성립하는지 확인
- 마들렌 ♥9 재료 모으기 ← 이미 하트 4 기준 분기가 있음(유지)
- 스텔라 ♥9·♥10 ← 배트리 ♥9 안경, 세라 ♥10 물약 분기가 있음(유지)
- **호박달 축제 시기**: 스텔라 ♥9는 축제 당일, 스트로 ♥10·마들렌 ♥10도 축제 날. 스텔라 ♥7 "축제까지 며칠", ♥10 "축제 끝나고 사흘째". 축제 이벤트들의 열리는 날을 정리해서, 같은 축제 날에 겹쳐도 서로 모순이 없는지(누가 어디 있는지) 확인하고, ♥10 스텔라는 "♥9 사흘 뒤"로 고정해.

## 4. 검증

1. 위 항목을 모두 고친 뒤 대본 HTML을 다시 만들어. 바뀐 줄은 노란 배경으로 표시하고, 맨 위에 "수정 목록" 섹션(번호 · NPC · 이벤트 · 전/후)을 넣어.
2. 검증 스크립트에 추가:
   - 1-1 분기 한정 표현 검사
   - 모든 `if_flag`가 참조하는 플래그가 어딘가에서 `set_flag`되는지, 세운 플래그가 어딘가에서 쓰이는지
   - `*_was_cold` 플래그가 이벤트 시작 시 지워지는지
   - 모든 NPC 파일에서 사람 NPC 고정 이름 0 건
   - 다른 NPC 진행 플래그(`xxx_hN`)를 참조하는 대사가 있으면, 그 플래그가 없을 때의 대체 대사도 있는지
3. 대표 플레이 경로 4 가지를 자동으로 끝까지 돌려서 대사를 이어 붙인 텍스트를 뽑아 줘: (1) 모든 선택 최고점, (2) 모든 선택 0점, (3) 서먹한 결말이 2~3 번 섞인 경로, (4) NPC 순서를 거꾸로 진행(레오→나비)한 경로. 이 4 개를 내가 읽어 볼 수 있게 파일로 줘.
