# 호박달 마녀학교 웹앱 UI 전면 개선 작업 지시서

배포 주소: https://magionacademy.web.app
지금 문제는 크게 네 가지야.
1. 글씨 가독성이 떨어져.
2. 버벅거리고 매끄럽게 굴러가는 느낌이 없어.
3. 화면마다 스크롤이 생겨. 예를 들어 물약 제조에서 솥을 누르면 아래로 또 내려가야 해.
4. 로그아웃, 내 아이템(가방), 내 정보(호감도 상태 등)가 전혀 없어서 웹앱 게임 UI로서 갖춰야 할 게 빠져 있어.

목표는 **모든 기능이 스크롤 없이 한 화면 안에서 보이고, 60fps로 부드럽게 돌아가는 모바일 우선 웹 게임 UI**야.
기존 게임 로직(이동, 대화, 제조, 호감도 데이터)은 유지하고, 화면 구조와 UI, 성능을 고쳐.

---

## 0. 먼저 현재 상태 측정 (고치기 전에 반드시)

1. 프로젝트를 로컬에서 실행하고, Playwright로 아래 3 가지 화면 크기에서 모든 화면을 스크린숏으로 찍어 `audit/before/`에 저장해.
   - 휴대폰 390×844, 태블릿 820×1180, PC 1440×900
   - 찍을 화면: 첫 화면(로그인), 마을 맵, 지도 패널, 대화창, 물약 제조, 상점, 그 밖에 있는 모든 패널
2. 화면마다 아래를 측정해서 표로 정리해.
   - 페이지 스크롤 발생 여부(`document.documentElement.scrollHeight > window.innerHeight`)
   - 계산된 글씨 크기가 14px 미만인 요소 수
   - 글씨와 배경의 명도 대비가 4.5:1 미만인 요소 수(axe-core 사용)
   - 터치 영역이 44×44px보다 작은 버튼 수
3. 성능 측정
   - Chrome Performance 트레이스로 맵에서 10 초 동안 걷기, 지도 열고 닫기, 물약 제조 1 회를 기록해서 평균 FPS, 긴 작업(50ms 이상) 수, 입력 지연을 측정해.
   - Lighthouse 모바일 점수(성능, 접근성)와 번들 크기, 이미지 총용량을 기록해.
   - 버벅임의 원인을 코드에서 찾아서 목록으로 정리해. 특히 아래 항목을 확인해.
     - 매 프레임마다 React(또는 프레임워크) 상태를 바꿔서 화면 전체가 다시 그려지는지
     - 캔버스를 쓰지 않고 DOM 요소 수백 개를 움직이는지
     - `setInterval`로 애니메이션을 돌리는지
     - Firebase(Firestore/Realtime DB)에 걸을 때마다, 클릭할 때마다 쓰기를 보내는지, 리스너가 중복으로 붙는지
     - 큰 PNG를 그대로 쓰는지, 스프라이트 시트 없이 이미지를 하나씩 불러오는지
     - 웹 폰트를 늦게 불러와서 글씨가 깜빡이는지
4. 위 결과를 `audit/REPORT.md`로 정리해서 먼저 보여 주고 작업을 시작해.

## 1. 화면 구조: 한 화면 게임 셸

### 1-1. 기본 원칙
- 앱 전체를 `height: 100dvh; overflow: hidden;`인 하나의 게임 셸로 만들어. **페이지 스크롤은 어떤 화면에서도 0.**
- 모든 기능은 게임 셸 안에서 열리는 패널(오버레이)로 보여 줘. 별도 페이지로 넘어가거나 아래로 길게 이어지는 화면은 없애.
- 목록이 길면 패널 **안쪽 영역만** 스크롤되게 해(가방 칸, 퀘스트 목록 등). 그것도 가능하면 탭이나 페이지 넘김으로 해결해.
- 휴대폰 노치와 하단 바를 고려해서 `env(safe-area-inset-*)` 여백을 넣어.
- 가로 모드와 세로 모드 모두 한 화면에 들어가게 레이아웃을 따로 잡아.

### 1-2. 화면 배치 (세로 모바일 기준)
```
┌──────────────────────────────┐
│ 상단 HUD                      │  높이 56px
│ [아바타][이름 Lv]  [날짜·시간·날씨] [골드] [☰] │
├──────────────────────────────┤
│                              │
│      게임 화면(캔버스 맵)       │  나머지 전체
│                              │
│                [상황 버튼]    │  ← 근처 대상이 있을 때만 (말하기/채집/제조)
├──────────────────────────────┤
│ 하단 메뉴바                   │  높이 64px
│ [가방] [지도] [관계] [일지] [메뉴] │
└──────────────────────────────┘
```
- PC(가로 넓은 화면)에서는 게임 화면을 가운데 두고 최대 폭을 잡아. 하단 메뉴바는 그대로 두거나 오른쪽 세로 메뉴로 바꿔도 돼. 패널은 화면 가운데 모달로 열어.
- 패널이 열려도 상단 HUD는 보이게 하고, 패널 오른쪽 위에 닫기(✕) 버튼, 바깥을 누르거나 Esc를 눌러도 닫히게 해.

### 1-3. 지금 버튼 정리
지금 상단 버튼(오늘, 말하기, 지도, 멀리, 밝게, 보내기)은 이름만 봐서는 뭘 하는지 알기 어려워. 아래처럼 다시 배치해.
- **오늘** → 상단 HUD의 날짜·시간·날씨 영역을 누르면 "오늘의 정보" 패널(오늘 일정, 날씨, 열린 이벤트)
- **말하기** → 하단 고정 버튼에서 빼고, NPC 근처에 가면 게임 화면 오른쪽 아래에 뜨는 **상황 버튼**으로. 대상에 따라 말하기, 선물하기, 채집하기, 제조하기로 글자가 바뀌어.
- **지도** → 하단 메뉴바 [지도]
- **멀리**(확대·축소로 보임) → 게임 화면 구석의 작은 확대/축소 버튼 + 모바일은 두 손가락 확대·축소, PC는 마우스 휠
- **밝게**(밝기로 보임) → [메뉴] → 설정 안의 밝기 조절
- **보내기**(선물이나 편지 보내기로 보임) → [관계] 패널 안의 NPC 상세에서 "선물 보내기"
- 기능이 다르면 코드에서 실제 기능을 확인하고 가장 맞는 자리로 옮겨. 옮긴 내역을 보고서에 적어.

## 2. 새로 만들 기능 (게임 UI 필수 요소)

### 2-1. 로그인 / 계정
- Firebase Auth를 쓰고 있다면 그대로 써. 첫 화면은 타이틀 + "시작하기" + 로그인 방식 버튼.
- [메뉴] 패널에 **내 계정** 영역: 로그인한 계정, 로그아웃 버튼(누르면 "정말 로그아웃할까요?" 확인), 저장 상태 표시("방금 저장됨").
- 로그아웃하면 타이틀 화면으로 돌아가.

### 2-2. 가방 (내 아이템)
- 하단 [가방]을 누르면 열려.
- 위쪽 탭: 전체 / 재료 / 물약 / 음식 / 선물 / 옷 / 중요
- 칸 격자(휴대폰 5 열, PC 8 열). 칸마다 아이콘 + 개수. 누르면 아래 상세 영역에 이름, 설명, 쓰임새, [사용] [선물하기] [버리기] 버튼.
- 칸이 많으면 패널 안쪽만 스크롤, 또는 페이지 넘김(1/3).
- 새로 얻은 아이템은 칸에 작은 점 표시.

### 2-3. 내 정보
- 상단 HUD의 아바타를 누르면 열려.
- 탭 1 **프로필**: 아바타 전신(앞모습, 돌려 보기), 이름, 학년·레벨, 경험치 바, 소지 골드, 입학한 지 며칠째인지, [꾸미기] 버튼(기존 캐릭터 꾸미기 화면으로)
- 탭 2 **능력치**: 채집, 제조, 요리, 낚시, 지식 등 지금 게임에 있는 능력치와 다음 단계까지 남은 값
- 탭 3 **업적·도감**: 모은 물약·물고기·식물 도감 칸 (아직 못 얻은 건 실루엣)

### 2-4. 관계 (호감도)
- 하단 [관계]를 누르면 열려.
- NPC 목록: 초상화, 이름, 하트 0~10(칸 채우기), 오늘 말 걸었는지 체크, 오늘 선물 줬는지 체크.
- NPC를 누르면 상세: 하트와 다음 하트까지 남은 호감도 바, 알아낸 좋아하는 선물·싫어하는 선물(직접 줘 보기 전에는 "???"), 본 하트 이벤트 목록(다시 보기 가능), **다음 이벤트 힌트**("비 오는 날 저녁, 등불 시장에서……"), [선물 보내기] 버튼.
- 호감도 데이터는 NPC 스토리 작업에서 만든 데이터 구조(`data/npc/...`, 하트 이벤트 조건, 플래그)를 그대로 읽어.

### 2-5. 일지 (퀘스트·할 일)
- 진행 중인 의뢰, 메인 스토리 진행, 오늘 열린 하트 이벤트 위치를 보여 줘.
- 항목을 누르면 지도에서 그 위치를 표시해 주고 [여기로 가기] 버튼.

### 2-6. 메뉴 / 설정
- 계정(2-1), 설정, 도움말, 크레딧.
- 설정: 배경 음악·효과음 크기, 대사 속도(느리게/보통/빠르게/즉시), 밝기, 글씨 크기(보통/크게), 화면 흔들림 끄기, 저사양 모드(효과 줄이기).
- 설정은 로컬과 계정에 같이 저장.

### 2-7. 알림
- 아이템 획득, 호감도 상승, 저장 완료 같은 알림은 화면 위쪽에 2 초 동안 뜨는 작은 토스트로 통일. 여러 개면 쌓이지 않고 차례로.
- 호감도가 오를 때는 NPC 머리 위에 하트 아이콘 연출 + 토스트 "나비 ♥ +1".

## 3. 물약 제조 화면 (스크롤 문제 대표 사례)

- 솥을 누르면 **게임 셸 안에서 제조 패널**이 열려. 아래로 내려가는 영역은 없어.
- 세로 모바일 배치:
```
┌ 물약 제조 ─────────────── ✕ ┐
│ [레시피 선택 ▼]  필요: ◯◯ ◯◯ │  ← 선택한 레시피와 필요 재료
│                              │
│         (솥 그림)             │  ← 넣은 재료가 솥 위에 아이콘으로 표시
│     넣은 재료: ① ② ③         │
│   [젓기] [불 세기] [완성]      │
├──────────────────────────────┤
│ 재료 칸 (가로로 넘기는 한 줄 또는 2 줄 격자) │
└──────────────────────────────┘
```
- PC 가로 배치: 왼쪽 재료 격자 / 가운데 솥 / 오른쪽 레시피와 결과.
- 재료는 눌러서 넣거나 끌어다 놓기 둘 다 돼야 해.
- 완성 연출(거품, 빛, 결과 물약 카드)도 패널 안에서 끝나고, [가방에 넣기] [한 번 더] 버튼으로 마무리.
- 상점, 요리, 낚시 결과 등 비슷한 화면도 같은 패널 틀을 써.

## 4. 글씨 가독성

- 본문 글꼴: **Pretendard**(또는 Noto Sans KR). 제목·버튼처럼 게임 느낌이 필요한 곳만 픽셀 글꼴(예: Galmuri11)을 쓰고, 긴 문장과 대사에는 픽셀 글꼴을 쓰지 마.
- 글꼴 파일은 직접 호스팅하고 `font-display: swap` + 미리 불러오기(preload). 한글 글꼴은 서브셋으로 줄여.
- 최소 크기: 대사 17px, 본문 15px, 보조 설명 13px(13px은 숫자·짧은 라벨에만), 버튼 15px 굵게. 설정에서 "크게"를 고르면 전체 +2px.
- 줄 간격 1.5, 대사창은 한 줄에 24~28 자 정도에서 줄바꿈.
- 맵 위에 바로 글씨를 올리지 말고 반투명 어두운 판(예: `rgba(20,13,30,.82)`) 위에 올려. 명도 대비 4.5:1 이상.
- 대사창: 화면 아래 1/3 높이 안, 초상화 + 이름표 + 대사. 글자가 한 자씩 나오는 효과는 설정 속도를 따르고, 화면을 누르면 즉시 전체 표시 → 한 번 더 누르면 다음 줄. 대사 기록(로그) 버튼.
- 숫자(골드, 개수)는 고정폭 숫자(`font-variant-numeric: tabular-nums`)로 흔들리지 않게.

## 5. 성능과 부드러움

### 5-1. 렌더링
- 맵, 캐릭터, NPC는 **캔버스 하나**(또는 PixiJS 같은 2D 렌더러)에서 `requestAnimationFrame`으로 그려. DOM은 HUD와 패널에만 써.
- 게임 루프 상태(위치, 애니메이션 프레임)는 프레임워크 상태에 넣지 마. 화면 다시 그리기를 일으키지 않는 별도 객체로 관리하고, UI에 필요한 값(골드, 시간)만 바뀔 때 갱신해.
- 캔버스는 `devicePixelRatio`를 반영하되 픽셀 아트는 정수 배율로 키우고 `image-rendering: pixelated`.
- 스프라이트는 시트(아틀라스) 하나로 묶고, 화면 밖 객체는 그리지 않아.
- 캐릭터 이동은 칸 단위로 뚝뚝 끊기지 않게 보간(lerp)하고, 카메라도 부드럽게 따라가게.
- 탭해서 걷기: 길 찾기(A*) 결과를 미리 계산하고, 목적지에 작은 표시를 띄워.

### 5-2. 데이터
- Firebase 쓰기는 즉시 보내지 말고 로컬 상태를 먼저 바꾼 뒤, 몇 초마다 또는 중요한 시점(장소 이동, 이벤트 종료, 창 닫기)에만 묶어서 저장해.
- 실시간 리스너는 필요한 문서에만, 화면을 떠나면 해제. 중복 리스너가 없는지 확인해.
- 저장 중·저장 완료·오프라인 상태를 HUD 구석에 작은 아이콘으로 보여 줘.

### 5-3. 불러오기
- 첫 화면에서 필수 리소스만 먼저 불러오고 진행 막대가 있는 로딩 화면. 나머지는 뒤에서 미리 불러오기.
- 이미지는 WebP/AVIF로 바꾸고, 큰 배경은 쪼개거나 압축해. 번들은 화면별로 나눠(code splitting).

### 5-4. 반응과 움직임
- 모든 버튼은 누르는 순간 반응(살짝 눌리는 효과 + 효과음)이 있어야 해. 입력부터 반응까지 100ms 이내.
- 패널 열고 닫기는 150~220ms의 `transform`/`opacity` 애니메이션만 써(`top`, `height` 애니메이션 금지).
- 저사양 모드나 운영체제의 "동작 줄이기" 설정에서는 애니메이션을 줄여.
- 목표: 중간급 휴대폰에서 평균 55fps 이상, 50ms 넘는 긴 작업이 걷기 중 0 회.

## 6. 디자인 시스템 (통일감)

- 색 토큰을 한곳(`theme.css` 등)에 정리해.
  - 배경 `#140D1E`(지금 theme-color 유지), 패널 `#211733`, 패널 테두리 `#3A2A55`
  - 강조 호박색 `#FF9A3C`(주요 버튼, 하트), 보조 보라 `#9B7BFF`, 성공 `#6FD08C`, 경고 `#FF6B6B`
  - 글씨 `#F6F0FF`, 보조 글씨 `#BDB0D6`
- 모서리: 버튼 12px, 패널 16px, 아이템 칸 8px.
- 버튼은 3 종류만: 주요(호박색 채움), 보조(테두리), 아이콘 버튼(원형 44px).
- 아이콘은 한 세트로 통일(가방, 지도, 하트, 일지, 메뉴, 설정, 닫기 등). 픽셀 스타일이면 16px 기준 그리드로 그려서 정수 배율로 키워.
- 패널 틀, 탭, 칸, 토스트, 확인 창을 공통 컴포넌트로 만들고 모든 화면이 이걸 쓰게 해.

## 7. 조작

- 터치 영역은 최소 44×44px.
- PC 단축키: I 가방, M 지도, R 관계, J 일지, Esc 패널 닫기·메뉴, Space/Enter 대사 넘기기, E 상황 버튼.
- 패널이 열려 있을 때는 맵 터치(걷기)를 막아서 잘못 걷지 않게.
- 길게 누르면 브라우저 메뉴가 뜨거나 글씨가 선택되지 않게(`user-select: none`, `-webkit-touch-callout: none`). 단, 입력창은 예외.

## 8. 작업 순서

1. 0 단계 측정 보고서 → 나에게 먼저 보여 줘.
2. 디자인 토큰과 공통 컴포넌트(패널, 버튼, 탭, 칸, 토스트, 확인 창)
3. 게임 셸(상단 HUD, 게임 화면, 하단 메뉴바, 상황 버튼)과 페이지 스크롤 제거
4. 렌더링·데이터 성능 개선(5 장)
5. 기존 화면을 패널로 옮기기: 지도 → 대화창 → 물약 제조 → 상점 등
6. 새 기능: 가방 → 내 정보 → 관계 → 일지 → 메뉴·설정·로그아웃
7. 글씨·대비·터치 영역 전체 점검
8. 검증(9 장) → 배포

단계마다 바뀐 화면 스크린숏을 `audit/after/`에 저장하고 짧게 보고해.

## 9. 검증 (자동 테스트로 만들어)

Playwright 테스트를 `tests/ui.spec.*`로 만들고, 3 가지 화면 크기(390×844, 820×1180, 1440×900)에서 모든 화면과 패널을 열어 아래를 확인해.

1. 페이지 스크롤 없음: `scrollHeight <= innerHeight`, `scrollWidth <= innerWidth`
2. 모든 패널이 화면 안에 완전히 들어옴(패널 bounding box가 뷰포트 안)
3. 계산된 글씨 크기 13px 미만 요소 0 개, 본문·대사 15px 미만 0 개
4. axe-core 명도 대비 위반 0 건
5. 터치 영역 44px 미만 버튼 0 개
6. 가방·내 정보·관계·일지·설정 패널이 열리고 Esc와 ✕로 닫힘
7. 로그아웃 → 타이틀 화면으로 이동, 다시 로그인하면 진행 상태 유지
8. 물약 제조: 솥 열기 → 재료 넣기 → 완성 → 가방에 들어감, 이 과정 동안 스크롤 0
9. 성능: 맵에서 10 초 걷기 트레이스에서 평균 FPS 55 이상, 50ms 넘는 긴 작업 0 회(데스크톱 CPU 4배 감속 기준으로도 측정해서 기록)
10. Lighthouse 모바일: 성능 80 이상, 접근성 90 이상

마지막에 `audit/before/`와 `audit/after/` 스크린숏을 나란히 놓은 비교 페이지(`audit/compare.html`)와, 측정 수치 전후 표를 보여 줘.
